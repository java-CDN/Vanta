# Engine build on GitHub Actions (S3)

`.github/workflows/engine-s3.yml` compiles `vanta-chromium.exe` on free
`windows-2022` runners, packages it and smoke-tests it. It is generated by
`engine/scripts/gen_s3_workflow.py`; edit the generator and re-run it, never the
YAML. Dispatch only (Actions → engine-s3 → Run workflow): a full chain takes
10–20+ runner hours.

## Chained stages

A full Chromium build does not fit in one 6-hour job, so the workflow has 10
identical jobs (`stage-1` … `stage-10`), each `needs` the previous one, as in
ungoogled-chromium-windows `reusable-build.yml`:

1. **Stage 1** prepares the tree exactly like S2 (`prepare.py` steps
   `source,windeps,prune,patch,domsub,rust,args,gngen` + `bindgen`), then runs
   `ci_ninja.py --canary`: it first compiles only the objects of the `.cc` files
   the Vanta series touches, so a broken Vanta patch fails within the first hour.
2. Every stage runs `ci_ninja.py` (ninja `-k 0`, under vcvars64) until
   `ninja_deadline_minutes` after the stage started, then stops ninja cleanly.
3. If ninja is not finished, `build/src` (sources + `out/Default`) is zipped
   with NTFS timestamps (4 GB volumes `build-state.zip.001`, …, plus
   `work.txt`) and uploaded as the artifact **`build-state`** (retention 1 day,
   overwritten by each stage). The volumes are written to `STATE_DIR`, on the
   other drive than the work dir when it has ≥ 60 GB free, so the tree and its
   zip never share a disk. The next stage downloads it, checks it was made in
   the same work dir (paths in `build.ninja` are absolute), unpacks it and
   continues.
4. A stage with failed edges (including a failed canary, or a `ci_ninja.py`
   crash after ninja ran) still archives and uploads its state, then stops the
   chain, so it can be resumed with `resume_run_id`.
5. `ci_ninja.py` keeps `out/Default/vanta_progress.json` (edges done / total)
   across stages; each stage exposes `edges_done`, `edges_total`, `finished`.

## Resync

`prepare.py patch` keeps a copy of every file the Vanta series touches (as it
was before the Vanta patches) in `src/.vanta_state/`. Every restored stage runs
`prepare.py --steps resync,args,gngen,bindgen --no-gn-check`. `resync` restores
those files, applies the current `engine/patches/series`, redoes domain
substitution on them and puts the old timestamps back on files whose content
did not change. So a patch fix pushed to `main` reaches a resumed build and
ninja only rebuilds what the fix affects.

## Final package + S5-lite smoke

The stage in which ninja finishes:

- `package_engine.py` builds `vanta-engine-win64.zip` (+ SHA-256) from the
  `FILES.cfg` entries, as ucw `package.py` does, without installer pieces or
  `.pdb`. Uploaded as artifact `vanta-engine-win64` (7 days).
- `smoke_s5lite.py` runs the real binary: version resource (ProductName
  "Vanta", version = `engine/VERSION`), starts without `--vanta-config`, bad
  signature → 86, missing pubkey → 86, wrong engine version → 87, valid signed
  config → starts. The Ed25519 key is generated per run. Logs: artifact
  `s5-lite-logs`.
- The `build-state` artifact is deleted.

The `complete` job fails unless some stage reported `finished=true`.

## Into the installer

The desktop installer bundles an engine only on request: run `ci.yml` by hand
(Actions → CI → Run workflow) with `engine_run_id` = the id of a finished S3 run
whose `vanta-engine-win64` artifact is still there (7 days). The desktop job
downloads it, `scripts/stage_engine.py` checks it against `SHA256SUMS` and
stages it, and `tauri build` ships it as `engine\` next to `vanta.exe`; the app
re-checks every file at start. Pushes and pull requests build the installer
without an engine. Details: README › Desktop app › Engine.

## Inputs

| Input | Default | Meaning |
|---|---|---|
| `jobs` | `2` | ninja `-j`. 2 as ucw uses: higher runs the 16 GB runner out of memory during ThinLTO. |
| `ninja_deadline_minutes` | `270` | Minutes after a stage starts at which ninja is stopped (leaves time to archive + upload within the 355-minute job limit). |
| `resume_run_id` | empty | Continue from the `build-state` artifact of that run (must be < 1 day old). Stage 1 skips the fresh prepare and resyncs the Vanta patches instead. Use it after fixing a patch that broke a stage. |
